# Política de Segurança

## Versões suportadas

Mantemos correções de segurança nas versões ativas de cada projeto. Consulte o README do repositório específico para saber quais versões estão em suporte ativo.

## Reportando uma vulnerabilidade

**Não abra uma issue pública para reportar vulnerabilidades de segurança.**

Divulgar detalhes publicamente antes da correção pode colocar usuários e clientes em risco.

### Canal preferencial — GitHub Private Vulnerability Reporting

Use o botão **"Report a vulnerability"** disponível na aba **Security** de cada repositório. Isso cria um advisory privado, visível apenas para os mantenedores.

### Canal alternativo — E-mail

Envie um e-mail para **seguranca@teranex.inf.br** com:

- Descrição do problema e componente afetado
- Passos para reproduzir ou prova de conceito
- Impacto estimado
- Sugestão de mitigação (se houver)

### Prazo de resposta

| Etapa | Prazo |
|---|---|
| Confirmação de recebimento | 72 horas |
| Avaliação de severidade | 7 dias |
| Correção (crítica/alta) | 30 dias |
| Correção (média/baixa) | 90 dias |

## Divulgação coordenada

Após a correção ser aplicada e disponibilizada, publicamos um security advisory com créditos ao pesquisador (se autorizado). Pedimos que aguarde a publicação oficial antes de divulgar externamente.

## Escopo

Esta política cobre todos os repositórios públicos da organização **teranex**. Para projetos de clientes (repositórios privados), entre em contato diretamente pelo e-mail acima.
